## 2. ADR

### ADR-009: 桌面模拟器 + 平台插件多轨

**决策**：PaymentManager 通过 `OS.get_name()` 检测平台，Android 走 GodotGooglePlayBilling 插件，iOS 走 InAppStore 单例（内置于 Godot iOS 导出模板），桌面/编辑器走内置模拟器。

**代价**：桌面模拟器无法测试真实的付款、退款、订阅流程。

**收益**：UI 开发和逻辑测试不需要真机，CI 可在 PC 上跑商店 UI 测试。模拟器有 0.2-0.5s 延迟和 90% 成功率，接近真实手感。

**平台路由逻辑**：
```gdscript
func _ready() -> void:
    is_android = OS.get_name() == "Android"
    is_ios = OS.get_name() == "iOS"
    if is_android:
        _billing = Engine.get_singleton("GodotGooglePlayBilling")
        # ...
    elif is_ios:
        _ios_store = Engine.get_singleton("InAppStore")
        # ...
    else:
        _is_simulator = true  # 桌面 fallback
```

### ADR-010: IAP 存档独立于 Run 存档

**决策**：购买记录（非消耗品 + 消耗品库存）存储在 `user://myspire_iap.json`，与 Run 存档（`user://myspire_run.json`）完全独立。

**原因**：
- 购买记录是跨 run 持久的（买了角色解锁永远拥有），而 run 存档会在每次 run 结束时清除
- Run 存档由种子确定性重建（ADR-003），不混入购买状态
- 退款时只需清除 IAP 存档，不影响当前 run 进度

### ADR-011: 三轨支付抽象 + SKU 双向映射

**决策**：PaymentManager 内部统一使用内部 SKU 作为商品标识，通过 `ContentRegistry.get_apple_id(sku)` / `get_sku_by_apple_id(apple_id)` 在 SKU 与平台商品 ID 之间双向翻译。UI 层和业务逻辑只接触内部 SKU，完全不感知平台差异。

**原因**：
- Google Play SKU 与 Apple Product ID 命名规则不同（Google 允许字母数字下划线，Apple 推荐 reverse-DNS 格式 `com.myspire.*`）
- 一个内部商品在两个平台有不同的商品 ID，但 UI 只需要显示一个名称
- 购买回调需要从平台 ID 反查内部 SKU 才能查找商品定义和应用效果

**代价**：iap_products.json 需为每个商品维护 `apple_id` 字段，新增商品时需要在两个平台的开发者后台分别创建条目。

**翻译链路**：
```
purchase(sku)                                # UI 调用，传入内部 SKU
  → ContentRegistry.get_apple_id(sku)        # 翻译为 Apple Product ID
  → _ios_store.purchase({"product_id": apple_id})  # iOS 平台调用

# iOS 回调
_on_ios_purchase_success(purchase)
  → ContentRegistry.get_sku_by_apple_id(apple_id)  # 反查回内部 SKU
  → _handle_successful_purchase(normalized, sku)    # 统一处理
```

**归一化**：iOS 回调中的 purchase Dictionary 被转换为与 Android 相同的标准格式（`product_id` = 内部 SKU，`purchase_token` = transaction_id），`_handle_successful_purchase` 无需感知平台差异。

## 3. 商品定义格式

商品数据驱动（ADR-002），定义在 `assets/content/iap_products.json`：

```json
{
  "products": [
    {
      "sku": "unlock_watcher",
      "apple_id": "com.myspire.unlock_watcher",
      "type": "non_consumable",
      "display_name": "观心者 · 紫衣",
      "description": "解锁第四位可选角色",
      "price_usd": 2.99,
      "icon": "👁️",
      "category": "character"
    },
    {
      "sku": "gold_pack_small",
      "apple_id": "com.myspire.gold_small",
      "type": "consumable",
      "display_name": "金币包 · 小",
      "description": "获得 500 金币",
      "price_usd": 0.99,
      "icon": "💰",
      "category": "currency",
      "reward_gold": 500
    }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `sku` | 内部商品 ID（统一标识，跨平台使用）|
| `apple_id` | Apple App Store Connect 商品 ID（reverse-DNS 格式，iOS 购买时翻译用）|
| `type` | `consumable`（消耗品）或 `non_consumable`（非消耗品）|
| `category` | UI 分组用：character / feature / currency / consumable / cosmetic |
| `price_usd` | 显示用价格（实际价格以平台返回为准）|
| `reward_gold` | 即时生效型消耗品标记。有此字段的商品消费后不加库存，直接转化为效果 |

**平台 ID 对照**：

| 内部 SKU | Google Play SKU | Apple Product ID | 类型 |
|----------|----------------|-------------------|------|
| `unlock_watcher` | `unlock_watcher` | `com.myspire.unlock_watcher` | 非消耗品 |
| `remove_ads` | `remove_ads` | `com.myspire.remove_ads` | 非消耗品 |
| `gold_pack_small` | `gold_pack_small` | `com.myspire.gold_small` | 消耗品 |
| `gold_pack_large` | `gold_pack_large` | `com.myspire.gold_large` | 消耗品 |
| `revive_token` | `revive_token` | `com.myspire.revive_token` | 消耗品 |
| `card_skin_gold` | `card_skin_gold` | `com.myspire.card_skin_gold` | 非消耗品 |

**消耗品子类型**：
- 即时生效型（`reward_gold` 字段）：消费后直接应用效果，不进入库存
- 库存型（无 `reward_gold`）：消费后存入 `SaveManager.add_consumable`，使用时调 `use_consumable`

## 4. 购买流程

### 4.1 非消耗品（角色解锁 / 去广告）

**Android 路径**：

```
ShopScreen          PaymentManager         Google Play         SaveManager
    │                    │                     │                    │
    │ purchase(sku)      │                     │                    │
    │───────────────────▶│ _billing.purchase()│                    │
    │                    │────────────────────▶│                    │
    │                    │ purchases_updated   │                    │
    │                    │◀────────────────────│                    │
    │                    │ verify_purchase_receipt()               │
    │                    │ acknowledgePurchase │                    │
    │                    │────────────────────▶│                    │
    │                    │ save_iap(sku, purchase)                  │
    │                    │────────────────────────────────────────▶│
    │ purchase_succeeded │                     │                    │
    │◀───────────────────│                     │                    │
```

**iOS 路径**：

```
ShopScreen          PaymentManager         InAppStore           SaveManager
    │                    │                     │                    │
    │ purchase(sku)      │                     │                    │
    │───────────────────▶│ get_apple_id(sku)   │                    │
    │                    │ _ios_store.purchase()│                   │
    │                    │────────────────────▶│                    │
    │                    │ purchase_success    │                    │
    │                    │◀────────────────────│                    │
    │                    │ get_sku_by_apple_id()│                   │
    │                    │ normalize purchase   │                   │
    │                    │ verify_purchase_receipt()                │
    │                    │ finish_transaction  │                    │
    │                    │────────────────────▶│                    │
    │                    │ save_iap(sku, purchase)                  │
    │                    │────────────────────────────────────────▶│
    │ purchase_succeeded │                     │                    │
    │◀───────────────────│                     │                    │
```

### 4.2 消耗品（金币包 / 续命币）

**核心差异**：
- Android: `consumePurchase(token)` → 异步回调 `_on_purchase_consumed`
- iOS: `finish_transaction({transaction_id})` → 无回调，`call_deferred` 触发 `_on_purchase_consumed`

```
                    │ consumePurchase / finish_transaction     │
                    │                     │                    │
                    │ has reward_gold?    │                    │
                    │  YES → 不加库存     │                    │
                    │  NO  → add_consumable(sku, 1)           │
                    │────────────────────────────────────────▶│
                    │                     │                    │
    │ purchase_succeeded │                     │                    │
    │◀───────────────────│                     │                    │
```

### 4.3 归一化 purchase Dictionary

iOS 回调的原始 purchase 与 Android 格式不同，PaymentManager 在 `_on_ios_purchase_success` 中统一归一化：

| 归一化字段 | Android 来源 | iOS 来源 |
|-----------|-------------|---------|
| `product_id` | `purchase.product_id`（= Google SKU = 内部 SKU） | `ContentRegistry.get_sku_by_apple_id(apple_id)` |
| `purchase_token` | `purchase.purchase_token` | `purchase.transaction_id` |
| `purchase_state` | `purchase.purchase_state` | 固定 `PurchaseState.PURCHASED` |
| `is_acknowledged` | `purchase.is_acknowledged` | 固定 `false`（iOS 无此概念） |
| `receipt` | 不存在 | `purchase.receipt`（base64，服务端验证用） |
| `platform` | 固定 `"android"` | 固定 `"ios"` |
| `original_json` | Google 返回的收据 JSON | 原始 iOS purchase 的 JSON 序列化 |

## 5. 恢复购买

```
用户点击"恢复购买"
    │
    ▼
PaymentManager.restore_purchases()
    │
    ├── Android: _billing.queryPurchases("inapp")
    │           → 返回账户所有未消费的购买
    │
    ├── iOS: _ios_store.restore_purchases()
    │        → restore_purchases_finished 信号
    │        → 每项购买归一化 + save_iap 重新应用所有权
    │
    └── 模拟器: 返回 SaveManager 中所有非消耗品
    │
    ▼
restore_completed(purchases)
    │
    ▼
ShopScreen 刷新所有商品卡片状态
```

**iOS 恢复的特殊处理**：
- iOS 的 `restore_purchases_finished` 返回的是 Array，每项需通过 `get_sku_by_apple_id` 反查内部 SKU
- 恢复的购买会重新调用 `SaveManager.save_iap` 确保非消耗品所有权在本地生效
- iOS 在应用启动时自动调用 `restore_purchases()`（Apple 最佳实践，确保跨设备同步）

## 6. 服务端验证流程（未来实装）

```
1. 客户端购买成功，获得归一化 purchase Dictionary:
   Android: { original_json, signature, product_id, purchase_token, platform: "android" }
   iOS:     { receipt, product_id, purchase_token, platform: "ios" }

2. NetworkClient.verify_purchase_receipt(purchase):
   按 purchase.platform 路由:

   Android: POST /api/iap/verify/google
   { original_json, signature, product_id, purchase_token }

   iOS: POST /api/iap/verify/apple
   { receipt, transaction_id, product_id }

3. C# 服务端:
   Android:
   - 调用 Google Play Developer API: purchases.products.get()
   - 用 Google Service Account 私钥验签
   - 验证 purchaseState == 1, productId 一致, consumptionState

   iOS:
   - 调用 App Store Server API: verifyReceipt
   - 用 App Store 共享密钥验证 receipt 签名
   - 验证 status == 0, product_id 一致

4. 验证通过 → 客户端执行消费/确认
   验证失败 → 发 billing_error，不发货
```

## 7. 安全考量

| 风险 | 措施 |
|------|------|
| 客户端伪造购买 | 服务端验证 receipt 签名（离线桩阶段本地信任，上线前必须改为强制在线）|
| 退款后仍可用 | Google Play: Voided Purchases API 推送撤销通知；iOS: App Store Server Notifications V2 |
| 重放攻击 | purchase_token / transaction_id 一次性使用，服务端记录已验证的 token 防重放 |
| 中间人篡改 | 使用 HTTPS + certificate pinning；Android 的签名由 Google 私钥保证，iOS 的 receipt 由 Apple 签名 |
| 模拟器刷购买 | Release 包检测 `OS.has_feature("editor")` 和 root/越狱状态，拒绝在非生产环境执行真购买 |
| iOS receipt 伪造 | 服务端用 App Store 共享密钥验证 receipt 的 base64 签名，不信任客户端传的任何明文字段 |

**当前原型状态**：`NetworkClient.verify_purchase_receipt` 离线时返回 `true`（本地信任）。上线前必须改为 `return false` 强制在线验证。

## 8. iOS 导出配置

### 8.1 Godot iOS 导出设置

InAppStore 单例内置于 Godot 4 iOS 导出模板，**无需额外插件**。需要在 Export Preset 中配置：

1. **Application/Info.plist** 添加：
   ```xml
   <key>SKPaymentPrivacy</key>
   <string>YES</string>
   ```

2. **Capabilities** 勾选 `In-App Purchase`

3. 确保 iOS 导出模板包含 `inappstore` 模块（标准模板已包含）

### 8.2 App Store Connect 配置

1. 在 App Store Connect > 你的 App > In-App Purchases 中为每个商品创建条目
2. Product ID 必须与 `iap_products.json` 中的 `apple_id` 完全一致
3. 设置价格层级（与 `price_usd` 对应的 Price Tier）
4. 填写本地化名称和描述
5. 提交审核（首次需要截图）

### 8.3 沙盒测试

1. App Store Connect > Users and Access > Sandbox Testers 创建测试账号
2. iOS 设备：设置 > App Store > Sandbox Account 登录测试账号
3. 真机运行 Godot 导出的 iOS 包，进入商店测试购买流程
4. 沙盒购买不会实际扣款

### 8.4 与 Android 配置对比

| 配置项 | Android | iOS |
|--------|---------|-----|
| 插件 | GodotGooglePlayBilling（需手动安装） | InAppStore（内置，无需安装）|
| 商品 ID 格式 | 字母数字下划线（`unlock_watcher`） | reverse-DNS（`com.myspire.unlock_watcher`）|
| 商品创建 | Google Play Console | App Store Connect |
| 测试环境 | 测试轨道 + 许可测试账号 | Sandbox Tester 账号 |
| 导出配置 | `project.godot` `[android] modules` | Export Preset Capabilities + Info.plist |
| 确认方式 | `acknowledgePurchase` (3 天内) | `finish_transaction` (处理完即调) |
| 消费方式 | `consumePurchase` | `finish_transaction` |
| 恢复购买 | `queryPurchases` | `restore_purchases` |
| 启动恢复 | 可选 | **必须**（Apple 最佳实践）|

## 11. 扩展指南

### 添加新商品
1. 在 `assets/content/iap_products.json` 的 `products` 数组加一项（包含 `sku` + `apple_id`）
2. 在 Google Play Console 创建 SKU 对应的商品
3. 在 App Store Connect 创建 `apple_id` 对应的商品
4. 如有特殊效果逻辑，在 `ShopScreen._on_purchase_succeeded` 中处理
5. 两个平台的商品定价可以不同（本地化价格由平台返回）

### 添加订阅商品
1. `iap_products.json` 加 `"type": "subscription"`（需同时配 `apple_id`）
2. PaymentManager 的 `query_sku_details` 需额外调用 Android `"subs"` 类型查询
3. 订阅需要定期验证（Android: Google RTDN；iOS: App Store Server Notifications V2）
4. 订阅状态由服务端管理，客户端不持久化

### 接入其他平台（Steam / Epic）
