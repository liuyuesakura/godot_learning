## 5. 推荐实施顺序

```
第 1 步（纯人工，可并行启动，周期最长）
  ├─ 注册 Apple Developer（$99）+ Google Play（$25）开发者账号
  ├─ 若国内上架：启动版号申请（周期 6~12 个月，最优先启动）
  └─ 签约短信服务商 + 报备签名模板

第 2 步（服务端，解锁联调）
  ├─ A-S1 JWT 中间件（地基）
  ├─ A-S2 exchange / A-S3~S4 短信登录
  └─ P-S1~S3 支付验证/消费

第 3 步（客户端接入，依赖第 1、2 步产出）
  ├─ P-C1 Release keystore → A-G1 SHA-1 → A-G2 插件 → 真机 Google 登录
  ├─ macOS 上 A-I3 Apple 插件 → iOS 沙盒
  └─ P-C2/C3 双端真机 IAP 测试

第 4 步（合规收尾，上架前）
  ├─ A-C1 用户协议/隐私政策页面
  ├─ A-C2 官方品牌贴图
  ├─ 国内：A-R1/R2 实名+防沉迷
  └─ A-C5 ADR-012 文档
```

**最短可玩路径**（只想真机跑通支付）：P-C1 生成 keystore → P-G1~G4 建号建商品加测试号 → P-G5 上传 AAB → 真机购买。此路径不依赖服务端（客户端离线信任桩会放行）。

## 6. 风险与注意

1. **服务端是最大缺口**：`Server/` 目录当前 0 个文件。所有"在线验证/在线换取"路径目前都是离线信任桩——**Debug 包可玩但不可上架**，上线前必须实装并把桩改为强制在线。
2. **控制台 ID 一致性**：商品 ID、包名、Bundle ID、SHA-1 任何一处不一致，真机调用直接静默失败。建议创建时逐字符复制 §4 表。
3. **Apple 审核 4.8**：提供第三方登录必须同时提供 Sign in with Apple——设计已合规，但 **iOS 插件（A-I3）是 iOS 上架的硬前置**，且依赖 macOS 环境。
4. **版号周期**：若目标含中国大陆，版号申请是全局最长路径（6~12 个月），应立即启动；在此之前国内版本须关闭 IAP 入口。
5. **测试账号隔离**：Google 许可测试与 Apple 沙盒账号都是**免费测试通道**，务必配置后再真机测试，避免真实扣款。
